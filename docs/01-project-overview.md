Spare Parts Management System

1. Project Introduction

The Spare Parts Management System is a software system designed to simplify the process of searching for spare parts, viewing product information, placing orders, and managing products and customer orders.

The system provides customers with access to product information and allows the store manager to manage products and monitor orders through a centralized platform.

2. Project Objectives

The main objectives of this project are:

To provide an easy way to search for spare parts.

To display product prices, technical specifications, and availability.

To allow customers to add products to a shopping cart and place orders.

To enable the store manager to add, update, and deactivate products.

To help customers track their orders.

To improve the organization and management of product and order information.

3. System Users

The main users of the system are:

1. Customer: The customer can search for products, view product details, manage the shopping cart, place orders, and track order status.

2. Store Manager: The store manager can add new products, update product information, deactivate products, view customer orders, and update order statuses.

4. Project Scope

4.1. In-Scope Features

The initial version of the system includes:

Product search by name or product code.

Viewing product prices, technical specifications, and availability.

Adding products to the shopping cart.

Updating product quantities in the shopping cart.

Registering customer orders.

Viewing order status.

Managing products by the store manager.

Managing customer orders by the store manager.

4.2. Out-of-Scope Features

The following features are not included in the initial version:

Real online payment gateway integration.

Automatic shipping and delivery management.

A separate mobile application.

AI-based product recommendations.

Automatic tax calculation and processing.

5. Project Deliverables

The project deliverables include stakeholder identification, user stories, product backlog, functional requirements, non-functional requirements, a Use Case Diagram, and an Activity Diagram illustrating the main order registration process.
